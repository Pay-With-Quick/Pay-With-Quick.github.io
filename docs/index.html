Integrate with Quick Pay by Bank QR

This hub helps EPOS and terminal providers integrate with Quick for payment creation, QR rendering, and transaction status updates.

Sandbox base URL: https://kypcw92mfm.eu-west-2.awsapprunner.com
Production base URL: shared during onboarding.

Quickstart

  1. Create payment: POST /api/v1/payments
  2. Render QR: GET /api/v1/payments/{id}/qr
  3. Track status: webhooks first, polling fallback
curl -X POST "https://kypcw92mfm.eu-west-2.awsapprunner.com/api/v1/payments" \
  -H "Content-Type: application/json" \
  -H "X-API-KEY: <merchant_api_key>" \
  -H "Idempotency-Key: 0f61f2e4-8f7e-49f9-9f91-6f44fdd2f478" \
  -d '{
    "userId": "f61c0ec7-0f83-414e-8e5f-aace86e0ed35",
    "merchantId": "b73e2aa0-52f2-4c5b-bba9-e737f548c197",
    "amount": 11.00,
    "currency": "GBP"
  }'

Authentication

Current v1 model uses merchant API keys.

  • Header: X-API-KEY: <merchant_api_key>
  • Create payment requires Idempotency-Key
  • Invalid/missing key returns 401
  • Inactive merchant returns 403

Security roadmap: move partner APIs to OAuth2 client credentials with scoped access (for example payments:create, payments:read).

Payments API

  • POST /api/v1/payments create payment
  • GET /api/v1/payments/{id} payment status
  • GET /api/v1/payments/{id}/qr QR image
  • GET /api/v1/payments/{id}/providers provider list
  • GET /api/v1/payments/{id}/redirect-uri authorization redirect
  • GET /api/v1/payments/summary?id={id}&type=internal summary

Webhooks and status

Payment completion is asynchronous.

  • Primary model: webhooks and backend event propagation to terminal
  • Fallback model: poll status every 2-5 seconds with timeout

TrueLayer events currently handled include:

  • payment_authorized
  • payment_executed
  • payment_settled
  • payment_failed
  • payment_reversed

Errors and idempotency

Use idempotency for safe retries on network/transient failures.

  • 200 success
  • 201 created
  • 400 validation error
  • 401 unauthorized
  • 403 forbidden
  • 500 server error
